# AuraGen — Adaptive Experience Intelligence

AuraGen is a full-stack prototype that detects interaction-friction signals and changes a complex financial application form into a guided wizard. It is designed for a final-year engineering demonstration and as a foundation for a future SaaS product.

## What is included
- Next.js 14 + React dashboard with responsive metric cards and an adaptive wizard.
- Node.js + Express + Socket.IO backend for real-time interaction telemetry.
- Transparent heuristic friction score (0–100), with capped contributions for hesitations, rapid/repeated clicks and validation errors.
- Local Ollama integration (`llama3.2:3b` by default) to generate concise interface copy.
- Safe simulated fallback if Ollama is offline, times out, or returns invalid output.
- Strict UI configuration boundary: the model may improve copy, but cannot execute code, add arbitrary fields, or change the approved field schema.
- Form values remain in browser state. Only interaction counters and a completed-field count are sent to the backend; raw field values are not sent to Ollama.
- Health/readiness endpoints, environment examples, Dockerfiles, Compose file, and backend unit tests.

> **Measurement note:** the score is a heuristic estimate of interaction friction. It is not a clinically validated measure of cognitive load, attention, frustration, or a user's mental state.

## Requirements
- Node.js 20.9+ (Node 22 recommended)
- npm
- Ollama (optional, for local LLM adaptation)
- VS Code recommended

## Run locally (recommended)

### 1. Start Ollama (optional but recommended)
Install Ollama, then run:

```bash
ollama pull llama3.2:3b
ollama serve
```

If Ollama is already running as a Windows background service, you may not need `ollama serve`. Confirm the model exists with `ollama list`.

### 2. Configure and start the backend
Open a VS Code terminal:

```powershell
cd AuraGen\backend
Copy-Item .env.example .env
npm install
npm run dev
```

Backend endpoints:
- http://localhost:4000/health
- http://localhost:4000/ready
- `POST http://localhost:4000/api/applications` — validates a demo application and returns a submission receipt without persisting applicant details.

### 3. Configure and start the frontend
Open a second VS Code terminal:

```powershell
cd AuraGen\frontend
Copy-Item .env.local.example .env.local
npm install
npm run dev
```

Open http://localhost:3000.

### 4. Demonstrate the application
1. Enter sample details in the financial form.
2. Click **Simulate confusion**.
3. Observe the interaction-friction score and adaptive wizard.
4. Use Back, Continue, and Return to full form. Entered values are retained in the current browser session.
5. On the final review step, click **Finish review**. The backend validates the four demo fields and returns a confirmation ID. The prototype does not save applicant data to a database.
5. The adaptation status indicates whether local Ollama generated the copy or the safe fallback was used.
6. Use **Reset demo** to clear browser state and server-side counters.

To verify genuine local LLM use, inspect the adaptation source in the dashboard. `Generated by local Ollama` means an Ollama response was parsed and accepted. `Safe fallback mode` means inference failed or was not enabled.

## Environment configuration

Backend `.env`:

| Variable | Default | Purpose |
|---|---|---|
| `PORT` | `4000` | HTTP and Socket.IO port |
| `CLIENT_ORIGIN` | `http://localhost:3000` | Allowed frontend origin(s), comma-separated |
| `AI_PROVIDER` | `ollama` | `ollama` or `simulated` |
| `OLLAMA_URL` | `http://127.0.0.1:11434/api/generate` | Ollama generate endpoint |
| `OLLAMA_MODEL` | `llama3.2:3b` | Installed local model |
| `AI_TIMEOUT_MS` | `12000` | Inference timeout |

Set `AI_PROVIDER=simulated` to disable Ollama. The app automatically falls back to deterministic copy if Ollama is unreachable.

## Docker

```bash
docker compose up --build
```

The backend container uses `host.docker.internal` to reach Ollama on the host. On systems where this hostname is unavailable, adjust `OLLAMA_URL`. The frontend browser connects to `localhost:4000`, so this Compose configuration is for local demonstration, not direct cloud production deployment.

## Architecture

```text
Browser (Next.js)
  ├─ React form + adaptive wizard
  ├─ Interaction telemetry hook
  └─ Socket.IO client
          |
          v
Node.js / Express / Socket.IO
  ├─ Input allowlisting and metric counters
  ├─ Friction scoring engine
  └─ Adaptation service
          ├─ Ollama local inference (JSON copy/config)
          └─ Deterministic safe fallback
```

## Security and privacy boundaries
- The browser sends interaction counters and a completed-field count, not raw form values.
- Do not add passwords, government identifiers, bank account numbers, or other sensitive fields without a separate privacy/security review.
- AI output is untrusted. The backend constrains copy length and returns the canonical approved field/step structure.
- The frontend renders only known React components and known field types; it never evaluates generated JavaScript or HTML.
- The current prototype has no user accounts, persistent database, tenant isolation, audit log, or production-grade rate limiting. Do not expose it publicly as-is.
- Before production, add authentication/authorization, per-user and per-IP rate limits, durable storage with retention controls, observability, secrets management, automated security testing, and deployment-specific CORS/socket policies.

## Azure-ready next steps
The code is containerized and configuration-driven. A production Azure deployment should add Azure Container Apps, Azure Container Registry, managed PostgreSQL, Key Vault, Application Insights, identity integration, CI/CD, private networking, and a managed or separately hosted inference endpoint. These services are recommendations; they are not provisioned by this ZIP.

## Known limitations
- Friction score weights are illustrative and should be calibrated with usability research.
- Browser movement and click signals are imperfect proxies and may produce false positives.
- The wizard is a controlled demo for the included financial form, not a general-purpose website auto-redesign engine.
- Session metrics are in memory and reset when a socket disconnects or backend restarts.
- No production SLA, load test, accessibility audit, or cloud deployment is claimed.
